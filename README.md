# MachineGuard AI — Predictive Maintenance & Machine Failure Risk Screening

**An end-to-end AI/ML portfolio project for an industrial problem.** It trains a machine-learning model on operating readings, evaluates it on a holdout set, and provides a Streamlit dashboard for single-machine and batch CSV assessments.

> **Important:** This is an educational proof of concept, not a certified industrial safety system. The UCI dataset used in this tutorial is synthetic (industrial-inspired), not real factory telemetry. Never use this model to control equipment or replace qualified maintenance engineers, manufacturer limits, alarms, or safety procedures.

---

## 1. The problem this project addresses

Factories and workshops can lose production time and money when equipment stops unexpectedly. Maintenance teams need a way to screen operating readings and decide which records should receive earlier human inspection.

MachineGuard AI demonstrates a basic condition-screening workflow:

1. Read six machine fields: product type, air temperature, process temperature, rotational speed, torque, and tool wear.
2. Clean the data and handle missing values.
3. Train a Random Forest classifier to estimate the dataset's machine-failure label.
4. Evaluate it with precision, recall, F1, average precision, ROC-AUC, and a confusion matrix.
5. Show a failure score and alert decision in a dashboard.
6. Score a complete CSV and download the results.

### What the model does — and does not do

The UCI target `Machine failure` labels whether a recorded observation is associated with a failure. This project predicts that label from the sensor fields in the same observation. It **does not** forecast failure in the next 24 hours, predict remaining useful life, identify the exact failed component, or calculate when a machine will break.

The model's `predict_proba` output is called a **failure score** in the app. It may not be a calibrated real-world probability. The alert threshold is a configurable decision setting, not a universal engineering limit.

## 2. Dataset

Main dataset: **UCI AI4I 2020 Predictive Maintenance Dataset**.

- UCI dataset ID: `601`
- 10,000 observations
- Machine operating fields plus failure labels
- UCI explicitly describes it as a synthetic dataset designed to reflect industrial predictive-maintenance data.
- License: Creative Commons Attribution 4.0 International (CC BY 4.0)
- Dataset DOI: `10.24432/C5HS5C`

Dataset page: <https://archive.ics.uci.edu/dataset/601/ai4i+2020+>

### Input columns used by this project

| Column | Meaning | Unit / example |
|---|---|---|
| `Type` | Product quality type | `L`, `M`, or `H` |
| `Air temperature [K]` | Air temperature | Kelvin |
| `Process temperature [K]` | Process temperature | Kelvin |
| `Rotational speed [rpm]` | Rotational speed | RPM |
| `Torque [Nm]` | Torque | Newton metre |
| `Tool wear [min]` | Accumulated tool wear | Minutes |
| `Machine failure` | Target label for training | `0` = no failure, `1` = failure |

The source also contains identifiers and failure-mode columns. They are not used as model inputs. In particular, failure-mode labels are excluded to avoid target leakage.

### If you do not have internet access

A small simulated CSV is included at `data/demo_machine_data.csv`. You can use it to practise the workflow offline. It is generated by this repository's script and is **not** the UCI data or real machine data.

## 5. Setup in VS Code (Windows)

### Step 1 — Install tools

Install:

1. Python 3.11 or 3.12 from <https://www.python.org/downloads/>. During installation, enable **Add Python to PATH**.
2. Visual Studio Code from <https://code.visualstudio.com/>.
3. The **Python** extension in VS Code.
4. Git from <https://git-scm.com/downloads> (needed for GitHub publishing).

Check Python in a new terminal:

```powershell
py --version
```

### Step 2 — Open the project

Extract the ZIP file. In VS Code, choose **File → Open Folder** and open `MachineGuard_AI_Student_Project`.

Open the terminal with **Terminal → New Terminal**.

### Step 3 — Create a virtual environment

Run these commands in the VS Code PowerShell terminal, from the project root:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, run this only for the current terminal and activate again:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

If you installed Python 3.12 instead, replace `py -3.11` with `py -3.12`.

### Step 4 — Download the UCI dataset

```powershell
python scripts/download_data.py
```

This creates `data/ai4i2020.csv`. The download needs an internet connection.

**Offline alternative:** the project already includes simulated data. You do not need to regenerate it, but you can run:

```powershell
python scripts/generate_demo_data.py
```

### Step 5 — Train the model

For the main UCI data:

```powershell
python -m src.train_model
```

For offline demo data:

```powershell
python -m src.train_model --data-path data/demo_machine_data.csv
```

After successful training, these files are created:

- `models/machine_failure_model.joblib`
- `reports/metrics.json`

The training script prints precision, recall, F1, average precision, and ROC-AUC. Your actual numbers may differ if you change the dataset, model settings, or threshold.

### Step 6 — Launch the dashboard

```powershell
streamlit run app.py
```

Streamlit will print a local address, usually `http://localhost:8501`. Open it in your browser.

### Step 7 — Run the tests

```powershell
pytest -q
```

## 6. How to use the dashboard

### Overview

See the purpose of the project and the saved holdout metrics.

### Single-machine check

Enter the six sensor fields and click **Assess machine**. The app shows:

- Model failure score
- Risk band
- Whether the score crossed your selected alert threshold
- A short, rule-based inspection checklist

The checklist is a demonstration based on ranges in the dataset. It is not a diagnosis and does not define safe limits for a real machine.

### Batch CSV check

Upload a CSV with these headers:

```csv
Type,Air temperature [K],Process temperature [K],Rotational speed [rpm],Torque [Nm],Tool wear [min]
M,300.1,310.2,1500,40.5,100
L,298.7,309.1,1650,35.2,74
```

The app adds `MachineGuard failure score`, `Risk band`, and `Alert`, then lets you download the scored CSV. The `Machine failure` target is optional for scoring. If it is present, the app can calculate retrospective metrics for that uploaded file; those metrics are not a fresh independent test.

### Model performance

Review holdout precision, recall, F1, average precision, ROC-AUC, the confusion matrix, and permutation feature importance.

## 7. Important ML concepts demonstrated

### Class imbalance

Machine failures are much less common than non-failures in the dataset. A model can achieve high accuracy by predicting “no failure” too often. This project uses `class_weight="balanced_subsample"` and reports precision, recall, F1, and average precision alongside accuracy.

- **Recall:** Of the actual failure cases, how many did the model flag?
- **Precision:** Of the cases flagged by the model, how many were actual failures?
- **F1:** A balance between precision and recall.
- **Average precision:** A useful summary of precision/recall performance across score thresholds when the positive class is rare.
- **Confusion matrix:** Shows true negatives, false positives, false negatives, and true positives.

### Alert threshold

The default threshold is `0.25`. Lowering it generally flags more records, which can increase recall but may also increase false alarms. The correct threshold depends on inspection capacity, failure consequences, and validated operating data. Do not choose it from accuracy alone.

### Leakage prevention

The model uses only operating readings. ID fields and failure-mode labels such as `TWF`, `HDF`, `PWF`, `OSF`, and `RNF` are not supplied to the classifier.

## 8. Publish to GitHub

First create an empty repository on GitHub, for example `machineguard-ai`. Then run these commands from the project folder:

```powershell
git init
git add .
git commit -m "Build MachineGuard AI predictive maintenance project"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/machineguard-ai.git
git push -u origin main
```

Replace `YOUR_USERNAME` with your GitHub username.

The `.gitignore` excludes the downloaded UCI CSV, trained model, and generated report by default. This keeps the repository smaller and avoids committing data/model artefacts unintentionally. For a reproducible portfolio submission, include a short training screenshot or results table in your repository README after you have trained it. If you want to deploy the dashboard on a cloud host, ensure the trained model and metrics are made available to the app through that host's supported build/storage process.

## 10. How to make this a stronger real-world project

1. Obtain permissioned sensor and maintenance logs from a local workshop, factory, college lab, or public industrial partner. Remove personal or confidential data.
2. Add machine ID and timestamps, then create time-based train/validation/test splits. Random splits alone do not prove future performance.
3. Define the business target with maintenance engineers: same-observation failure, failure within a defined future window, or remaining useful life. These are different ML tasks.
4. Compare Random Forest with Logistic Regression and Gradient Boosting using the same validation plan.
5. Add probability calibration and cost-based threshold selection using real failure and inspection costs.
6. Monitor missing sensors, data drift, model versions, and false alarms.
7. Run a pilot in **shadow mode** (recommendations only) before considering operational use.

A strong project is not just a high accuracy number. It is a well-defined problem, honest data documentation, leakage-safe evaluation, understandable trade-offs, and a responsible path to deployment.
